MES Platform 기준 문서 (Baseline)

이 문서는 프로젝트의 기본 방향과 규칙을 한 곳에 모아둔 기준 문서입니다.
모든 작업은 이 기준을 우선으로 삼아 진행합니다.

1) 문서 목적
- 프로젝트 범위와 구조를 명확히 하고, 앞으로의 개발 방향을 흔들리지 않게 유지합니다.
- 보안, 데이터 분리, UI/UX, 테스트, 배포 등 중요한 원칙을 팀 전체가 동일하게 이해하도록 합니다.
- 초보자도 쉽게 이해할 수 있도록 용어를 가능한 한 풀어서 설명합니다.

2) 플랫폼 구성(전체 구조)
- 제조장비 ↔ (옵션) IoT 인터페이스(Edge Gateway, 장비와 서버를 이어주는 중간 장치) ↔ AI Middleware ↔ MES Web Service
- MES Web Service: 화면과 업무 기능을 제공하는 웹 시스템
- AI Middleware: 장비 데이터 수집, 분석, 정규화(표준화), 저장을 담당하는 중간 서비스
- IoT 인터페이스(Edge Gateway): 장비가 직접 서버와 연결이 어려울 때 사용하는 경량 장치

3) 개발/운영 환경 기본 원칙
- 전자정부 표준프레임워크(eGovFrame)를 기반으로 개발, 실행, 운영을 모두 수행합니다.
- Windows, Linux 모두에서 운영 가능해야 합니다.
- 로컬 PC, 워크스테이션, 서버, 클라우드 어디서든 운영 가능해야 합니다.

4) 보안 및 데이터 분리(최우선)
- 멀티테넌트(여러 기업이 동시에 사용하는 구조)에서 기업 데이터는 반드시 분리되어야 합니다.
- 전송 구간은 HTTPS(TLS)로 암호화합니다.
- DB 저장 시 개인정보/민감정보는 AES-256 수준으로 암호화합니다.
- 비밀번호는 복호화가 불가능한 해시(bcrypt/argon2)로만 저장합니다.
- 토큰/키/비밀번호는 소스코드에 하드코딩하지 않습니다.

5) UI/UX 기준
- 화면 범위: SCR-0001 ~ SCR-0049 전체를 대상으로 합니다.
- JSP 기반 페이지 + 공통 레이아웃 + 공통 그리드/모달/폼을 재사용합니다.
- 필요 시 일부 화면만 SPA 스타일로 점진적으로 강화합니다.
- 라우트/화면명/필드 정의는 참고 문서를 기준으로 정합성을 맞춥니다.

6) AI Middleware 기준
- 원본 데이터는 절대 수정하지 않고 그대로 보관합니다(재처리를 위해 필요).
- 자동 분석 결과는 “제안” 수준이며, 승인된 매핑 규칙이 있어야만 표준 DB에 저장합니다.
- 신뢰도가 낮거나 검증 실패 시 Quarantine(격리 저장)로 보냅니다.
- 제어(쓰기) 신호는 읽기보다 더 엄격한 승인 및 권한 통제가 필요합니다.

7) 로그 및 감사
- 원시 로그는 일정 기간 보관하고, 관리자 화면에서 기간/기업별 조회가 가능해야 합니다.
- 로그인/비밀번호 변경/사용자 관리 등 보안 이벤트는 감사 로그로 남깁니다.
- 모든 요청에는 추적을 위한 Correlation ID를 부여합니다.

8) 개발 절차(프로세스)
- S0~S9 단계별 개발 프로세스를 따르며, 단계마다 산출물을 작성합니다.
- 요구사항(SRS), UI/UX 설계, ERD, API 문서, 테스트 결과는 반드시 기록합니다.
- 단위 테스트 + 통합 테스트 + 보안/성능 테스트를 수행합니다.

9) 응답/작업 규칙(중요)
- 모든 질문과 답변은 한국어로 진행합니다.
- 초보자(일반인)도 이해할 수 있도록 자세하게 설명합니다.
- 이 규칙은 앞으로의 모든 작업에서 반드시 지켜야 합니다.

10) 소스코드 주석 작성 규칙(매우 중요)
- 모든 소스코드는 목적과 기능을 설명하는 주석을 반드시 포함합니다.
- 핵심 로직은 목적(목표), 기능, 이유를 한국어로 자세히 설명합니다.
- 초보자도 이해할 수 있도록 쉬운 한국어 표현을 사용합니다.
- 유지보수(수정/추가/확장) 관점을 고려한 주석을 작성합니다.
- 중복 최소화, 재사용성 강화, 간결한 코드 작성 원칙을 유지합니다.
- 최신 정보/최신 기준을 반영하여 최고 품질을 지향합니다.

11) 확정된 결정 사항(중요)
- 멀티테넌트 분리 방식: 기업별 DB 분리를 기본 원칙으로 적용합니다.
- 라우트(화면 주소) 기준: UI/UX 상세 설계 문서를 최종 기준으로 사용합니다.
- 로그인 화면 방식: 전용 로그인 페이지(`/login`)로 통일합니다.
