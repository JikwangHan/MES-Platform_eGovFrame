# AI Middleware 추천 요청사항 정리

## 목적
- AI Middleware 전용 Chat에서 일관된 응답 형식을 유지합니다.
- 진행 순서와 자동화 범위를 명확히 합니다.
- 커밋/PR 정책 준수를 빠르게 확인할 수 있도록 합니다.

## 적용 규칙
### 1) 응답 형식(항상 고정)
- 서두 4줄을 반드시 출력합니다.
  - 프로젝트 전체 공정률
  - 현재 진행 단계
  - 현재 단계 진행률
  - Context : xx% Used
- Context 문구 규칙:
  - Context가 70% 이상일 때만 “85% 이상이면 50% 미만으로 자동 조정” 문장을 출력합니다.
  - Context 표기는 `Context : 21% Used` 형식으로 간단히 표시합니다.

### 2) 답변 스타일
- 모든 답변은 한국어로 작성합니다.
- 초보자도 쉽게 이해할 수 있도록 순서/방법을 상세히 설명합니다.
- 복붙 가능한 명령어/코드 블록을 포함합니다.

### 3) 작업 추천 방식
- 다음 작업은 반드시 “추천 1) … / 추천 2) …” 형식으로 제시합니다.
- AI Middleware 전용 Chat에서는 IoT-Edge-Gateway 관련 추천을 제외합니다.
- 사용자가 “추천 1)부터 자동 진행”을 요청하면 추천 1부터 자동으로 수행합니다.

### 4) 코드/문서 주석 규칙
- `docs/BASELINE.md`의 주석 규칙을 기준으로 적용합니다.
- 모든 클래스/메서드는 목적/기능을 설명하는 한국어 주석을 포함합니다.
- 파이프라인 핵심 로직(수신→정규화→분류→검증→저장/격리)은
  목적/기능/이유를 상세히 서술합니다.
- 원본 저장, 격리, 검증 실패 분기 등 핵심 지점은
  “왜 필요한지”를 초보자 관점에서 풀어 씁니다.

### 5) 커밋/PR/머지 정책
- 커밋 메시지는 한글로 상세 작성합니다.
  - 변경 요약/이유/검증 방법/결과/주의/다음 작업 포함
- 민감정보(로컬 경로, 계정, 토큰 등)는 로그/문서/커밋 메시지에 남기지 않습니다.
- PR 기준은 “코드 + 스모크(또는 테스트) + 문서 증빙” 3종 세트입니다.
- PR 머지는 웹 UI 대신 `gh pr merge`로 처리합니다.
