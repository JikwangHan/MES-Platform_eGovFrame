# AI Middleware KCMVP 적용 범위 및 패턴 결정안(v0.2)

## 목적
- KCMVP를 “암호 사용”이 아니라 “검증필 암호모듈을 제품 구성요소로 채택”하는 설계 요구사항으로 정리합니다.
- AI Middleware에서 반드시 적용해야 하는 보안 구간과 패턴(A/B/C)을 확정합니다.

## 문서 정합성 기준
- 암호화 대상/전송 정책은 `docs/AI_MIDDLEWARE_KCMVP_ENCRYPTION_POLICY.md` 기준을 따릅니다.
- 키 생성/보관/회전/폐기는 `docs/AI_MIDDLEWARE_KCMVP_KEY_POLICY.md` 기준을 따릅니다.
- 모듈 후보 확정/운영 환경 검증은 `docs/AI_MIDDLEWARE_KCMVP_MODULE_CHECKLIST.md` 기준을 따릅니다.

## 적용 범위(보호 구간)
AI Middleware 관점의 보호 대상은 아래와 같습니다.

1) 저장 데이터 암호화
- Raw 저장(원본 payload, 해시, 메타 정보)
- Standard 저장(정규화/검증 통과 데이터)
- Quarantine 저장(검증 실패 데이터 및 사유)
- Unknown 저장(미정의 입력 및 스캔 결과)

2) 전송 구간 보호
- Ingress HTTP/TLS(장비->AI Middleware)
- 내부 서비스 간 호출(TLS 적용 필요 구간)

3) 무결성 및 서명
- 수신 원본 로그 변조 방지
- 재처리/재전송 큐 데이터 무결성 확인

4) 키 관리
- 키 생성/저장/회전/폐기 정책
- 키 유출 시 대응 및 접근 통제

## 적용 패턴 후보(문서 기준)
- 패턴 A: 검증필 SW 암호모듈 내장
  - 장점: 도입 빠름, 비용 낮음
  - 주의: 모듈 버전 고정 및 해시 일치 관리 필수
- 패턴 B: HSM 연동
  - 장점: 키가 서버 밖에 존재, 보안 강화
  - 주의: 비용/운영 복잡도 증가
- 패턴 C: 하이브리드(HSM + 검증필 SW)
  - 장점: 키 보호와 성능 균형
  - 주의: 키 래핑 구조 설계 필요

## AI Middleware 기본 적용안
- 기본 권장: 패턴 A
  - 적용 대상: 저장 데이터 암호화, 전송 구간 보호
  - 이유: 초기 도입 리스크와 일정 최소화
- 보안 등급 상향 시: 패턴 C
  - 적용 대상: 키 래핑/마스터키 보호가 필요한 운영 환경
  - 전제: HSM 운영 체계 및 장애 대응이 준비된 경우

## 구성요소별 적용 매핑
- Ingress/HTTP 수신
  - TLS 적용(검증필 모듈 기반)
  - 인증서 운영 정책 문서화
- Store/Quarantine/Unknown 저장
  - 민감 컬럼(예: payload, deviceId, sourceIdHash) 암호화
  - 키 회전 정책 적용
- Pipeline 로그/결정 로그
  - 로그 위변조 방지(해시/서명)

## 설계 결정 항목(확정 대상)
1) 패턴 선택(A 또는 C) - 기본 A, 상향 시 C
2) 암호화 대상 필드(최소 집합 정의)
3) TLS 운영 방식(인증서 발급/회전 주기)
4) 키 관리 주기(생성/회전/폐기)
5) 검증필 모듈 후보 및 운영 OS/JDK 호환성(체크리스트 기준)

## 산출물(예비검토 대응 기준)
- 기본/상세 설계서(모듈 경계, 인터페이스, 오류 상태, 자기시험)
- 형상관리 문서(소스/빌드/해시/릴리즈 태그)
- 시험서(기능/부정/오류 유도 시험 결과)
- 테스트 스크립트(재현 가능 수준)
- 운영/관리자 안내서(키 생성/교체/폐기/복구)
