확정된 결정 사항 기록

이 문서는 프로젝트에서 이미 확정한 결정 사항을 기록합니다.
나중에 방향이 흔들리지 않도록 변경 이력을 남기는 용도입니다.

1) 멀티테넌트 분리 방식
- 결정: 기업별 DB 분리
- 이유: 보안 사고 위험을 최소화하고, 기업 간 데이터 완전 분리를 보장하기 위함

2) 라우트(화면 주소) 기준
- 결정: UI/UX 상세 설계 문서를 최종 기준으로 사용
- 이유: 화면 목적, 입력, 버튼, 권한 등이 가장 상세하게 정의되어 있음

3) 로그인 화면 방식
- 결정: 전용 로그인 페이지(`/login`)로 통일
- 이유: 화면 구조가 단순하고 초보자에게 이해가 쉬움

4) 권한 정책(메뉴/버튼/API)
- 결정: 서버에서 역할별 권한을 확정하고 UI는 해당 권한만 표시
- 이유: 클라이언트 조작으로 인한 무단 접근을 차단하기 위함

5) 감사 로그 저장 방식
- 결정: IP/UA/상세정보는 해시로 저장하고 원문은 남기지 않음
- 이유: 민감정보 유출 위험을 줄이면서 추적 가능성을 유지하기 위함
