# AI Middleware KCMVP 키 관리 정책(v0.2)

## 목적
- KCMVP 요구사항을 충족하기 위한 키 관리 정책을 정의합니다.
- 운영/감사/시험기관 대응 시 일관된 기준을 제공합니다.

## 문서 정합성 기준
- 적용 범위/패턴은 `docs/AI_MIDDLEWARE_KCMVP_SCOPE.md` 기준을 따릅니다.
- 암호화/TLS 운영은 `docs/AI_MIDDLEWARE_KCMVP_ENCRYPTION_POLICY.md` 기준을 따릅니다.
- 모듈 후보 확정/운영 환경 검증은 `docs/AI_MIDDLEWARE_KCMVP_MODULE_CHECKLIST.md` 기준을 따릅니다.

## 적용 범위
- AI Middleware 저장 암호화(원본/표준/격리/Unknown)
- 전송 구간 TLS 인증서/키
- 로그/이벤트 무결성 서명 키

## 키 분류
1) 데이터 암호화 키(DEK)
- Raw/Standard/Quarantine/Unknown 저장 데이터 암호화에 사용
2) 키 암호화 키(KEK)
- DEK 보호(래핑) 용도
3) 서명 키
- 로그/이벤트 무결성 보장
4) TLS 키/인증서
- 전송 구간 보호

## 패턴별 키 보관 방식
- 패턴 A(검증필 SW 모듈)
  - KEK/DEK는 검증필 모듈 기반 보호 저장소에 보관
  - 운영체제 계정 권한으로 접근 통제
- 패턴 C(하이브리드)
  - KEK는 HSM에 보관(키 외부 노출 금지)
  - DEK는 HSM에서 래핑 후 저장

## 키 생성 정책
- 검증필 암호모듈의 키 생성 API만 사용
- 키 길이/알고리즘은 검증필 목록 기준 준수
- 키 생성 이벤트는 감사 로그에 기록

## 키 저장 정책
- 평문 저장 금지
- 키 파일/키스토어 접근 권한 최소화
- 키 저장 위치는 운영 문서에 명시

## 키 회전 정책
- 기본 주기: 6~12개월(운영 환경에 맞게 조정)
- 회전 시 신규 키 발급 → 기존 데이터 점진적 재암호화
- 회전 이력 및 담당자 기록 유지

## 키 폐기 정책
- 폐기된 키는 복구 불가 상태로 처리
- 폐기 절차는 운영자 승인 이력 남김

## 키 유출 대응
1) 즉시 키 폐기
2) 신규 키 발급 및 재암호화
3) 로그 분석 및 영향 범위 산정
4) 감사 보고 체계 마련

## 운영 절차(요약)
1) 초기 키 생성
2) 키 등록 및 접근 권한 설정
3) 정기 회전 계획 실행
4) 폐기 및 감사 로그 보관

## 검토 필요 항목(확정 대상)
- 회전 주기 확정(운영 환경 기준 반영)
- 키 보관 위치(경로/키스토어) 확정
- 키 유출 대응 보고 체계 확정
- 모듈 후보 확정 시 KEK/DEK 보관 방식 재확인
