# AI Middleware KCMVP 모듈 후보 확정 및 운영 환경 검증 체크리스트(v0.2)

## 목적
- AI Middleware 상용화 단계에서 사용할 KCMVP 검증필 암호모듈 후보를 확정하기 위한 기준과 절차를 정리합니다.
- 운영 환경(OS/JDK/아키텍처)에서의 호환성 및 형상 검증 절차를 명확히 합니다.
- 초보자도 따라 할 수 있도록 단계별 체크리스트로 제공합니다.

## 문서 정합성 기준
- 적용 범위/패턴은 `docs/AI_MIDDLEWARE_KCMVP_SCOPE.md` 기준을 따릅니다.
- 암호화/TLS 운영은 `docs/AI_MIDDLEWARE_KCMVP_ENCRYPTION_POLICY.md` 기준을 따릅니다.
- 키 생성/보관/회전/폐기는 `docs/AI_MIDDLEWARE_KCMVP_KEY_POLICY.md` 기준을 따릅니다.

## 적용 전제(개발/상용화 분리)
- 개발/PoC: 무료 오픈소스 또는 KISA 표준 알고리즘 소스 사용 가능
- 상용화: KCMVP 검증필 모듈로 “암호모듈만 교체” 구조 유지
- CryptoService 경계 + 암호문 컨테이너 포맷 고정
- 패턴 C 기준: HSM 인터페이스 유지, 개발 단계는 실제 장비 연동 비활성

## 1) 후보 모듈 선정 기준
1.1 기능/보안 기준
- KCMVP 검증필 상태(유효 기간, 인증서 상태)
- 요구 알고리즘 지원 여부(예: AES-GCM/CCM, SHA-2 계열, HMAC 등)
- FIPS/국가 표준 준수 여부(필요 시)
- 난수 생성기 품질 및 자기시험(Self-test) 지원 여부

1.2 제품/운영 기준
- 상용 라이선스 조건(유지보수 기간, 업데이트 정책)
- 공급사 지원 체계(긴급 패치, 취약점 대응, SLA)
- 장기 지원(LTS) 계획 및 버전 고정 가능 여부
- 성능 요구 충족 여부(암호화/복호화 처리량, 지연)

1.3 통합/교체 기준
- CryptoService 인터페이스와의 교체 용이성
- 기존 암호문 컨테이너 포맷 유지 가능 여부
- 키 관리 정책(생성/회전/폐기) 준수 가능 여부

## 2) OS/JDK/아키텍처 호환성 체크
2.1 운영 환경 정보 수집(필수)
- 운영 OS 종류/버전(예: Windows Server, Linux 배포판/버전)
- JDK 버전(예: 11/17 등) 및 벤더(OpenJDK/Oracle 등)
- CPU 아키텍처(x86_64, ARM64 등)
- 컨테이너 사용 여부(Docker/K8s) 및 베이스 이미지

2.2 모듈 호환성 확인(필수)
- 모듈이 지원하는 OS/JDK/아키텍처 매트릭스 확인
- 네이티브 라이브러리 의존성 여부 및 배포 방식 확인
- JCE 정책/프로바이더 등록 방식 확인(보안 정책 충돌 여부)
- TLS 스택 호환성 확인(필요 시)

2.3 사전 리스크 점검(권장)
- 운영 환경에서 파일 권한/보안 정책 제약 여부
- 라이선스 키/인증서 로딩 방식(환경변수/파일)
- 장애 발생 시 폴백 전략(모듈 로딩 실패 시 동작)

## 3) 검증필 모듈 해시/형상 검증 절차
3.1 준비
- 공급사로부터 전달받은 배포물(바이너리/서명/해시)
- 배포 버전명, 빌드 번호, 릴리즈 노트 확보

3.2 검증 절차
1) 배포물 무결성 확인
   - 공급사 제공 해시값과 로컬 해시값 일치 확인
2) 형상 정보 기록
   - 버전/빌드/파일명/해시를 문서로 기록
3) 서명 검증(제공 시)
   - 서명/인증서 유효성 확인 및 검증 로그 저장
4) 재현성 확인(가능 시)
   - 동일 환경에서 동일 해시 재현 여부 확인

3.3 기록/보관
- 검증 결과를 문서로 남기고 변경 이력 관리
- 운영 배포 기준 파일에 “확정 해시”만 등록

## 4) 운영 점검 체크리스트
4.1 배포 전 점검
- 운영 환경 정보(2.1) 최신화 완료
- 모듈 버전/해시 확정 및 검증 완료
- CryptoService 교체 테스트 완료
- 키 관리 정책 문서 반영(생성/회전/폐기/복구)

4.2 배포 후 점검
- 모듈 로딩 및 자기시험 통과 여부 확인
- 주요 암호 API 정상 동작 확인
- 로그/감사 이벤트 정상 기록 확인
- 성능 영향(지연/처리량) 허용 범위 확인

4.3 운영 중 상시 점검
- 취약점 공지 모니터링 및 긴급 패치 절차
- 키 회전 주기 준수 여부
- 인증서/라이선스 만료 알림 체계
- 장애 대응 절차(폴백/복구/보고) 문서화

## 5) 산출물(최소)

- 운영 환경 호환성 체크 결과

- 운영 점검 체크리스트(완료/미완료 상태)

- 공급사 제공 해시값(SHA-256 등)
- 서명/인증서 제공 여부 및 검증 절차
- KCMVP 인증서 사본 및 유효기간 정보
- 지원 OS/JDK/아키텍처 매트릭스
- 네이티브 의존성/설치 가이드
- 취약점 공지 및 긴급 패치 정책

3) 공급사 제공 해시값(SHA-256 등)
4) 서명/인증서 제공 여부 및 검증 절차
5) KCMVP 인증서 사본 및 유효기간
6) 지원 OS/JDK/아키텍처 매트릭스
7) 네이티브 의존성/설치 가이드
8) 취약점 공지 및 긴급 패치 정책

## 7) 무료 오픈소스 적용 결정(개발/PoC)
- 현재 단계는 비용 발생 없는 무료 오픈소스 사용이 확정됨
- 상용화 전환 시 KCMVP 검증필 모듈로 “암호모듈만 교체” 구조 유지
- 후보 모듈은 추후 확정되며, 공급사 자료는 상용화 전환 시점에 수집

### 7.1 후보 모듈 상태(임시)
- 후보 모듈명/버전/벤더: 미확정(무료 오픈소스 기반 적용)
- 공급사 해시/서명: 미확정(상용화 전환 시 공급사 자료로 대체)
- 운영 호환성: OS/JDK/아키텍처 기준에 따라 적용
